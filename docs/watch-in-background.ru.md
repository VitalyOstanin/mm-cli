# Запуск watch в фоне

`mm-cli watch --reactions --notify` показывает уведомление на рабочем столе,
когда кто-то ставит реакцию на ваше сообщение. Чтобы получать их весь день,
команда должна работать в фоне. Здесь описан рекомендуемый способ для Linux,
пользовательская служба systemd, и альтернативы.

English version: [watch-in-background.md](watch-in-background.md).

## Что даёт служба

Пример unit: [docs/examples/mm-cli-watch.service](examples/mm-cli-watch.service).

- Запускается вместе с графической сессией и останавливается при выходе
  (`PartOf=` и `WantedBy=graphical-session.target`). Токен читается из
  защищённого хранилища ОС, которое доступно только в этой сессии.
- После сбоя (падение, потеря сети, завершающая команду) перезапускается
  через 30 секунд (`Restart=on-failure`, `RestartSec=30`).
- Если сессии нет или она истекла, mm-cli показывает одно уведомление
  «mm-cli: sign in again» и завершается с кодом 3. Unit по этому коду не
  перезапускается (`RestartPreventExitStatus=3`): перезапуск не поможет, а
  цикл только повторял бы уведомление.
- Обычная остановка не считается сбоем: mm-cli завершается с кодом 143 по
  SIGTERM, а `SuccessExitStatus=143` не даёт unit попасть в состояние
  `failed` при каждом `systemctl --user stop` и при каждом выходе из сессии.
- Вывод идёт в журнал; запуск, остановку и состояние показывает
  `systemctl --user`.

## Установка

Из корня репозитория:

```sh
mkdir -p ~/.config/systemd/user
cp docs/examples/mm-cli-watch.service ~/.config/systemd/user/
command -v mm-cli     # абсолютный путь к бинарнику
```

Исправьте `ExecStart=` в скопированном файле. systemd нужен абсолютный путь к
бинарнику. Пример предполагает `~/.local/bin/mm-cli` (`%h` — домашний
каталог); `go install` кладёт бинарник в `$(go env GOPATH)/bin` (или
`$GOBIN`), поэтому впишите вывод `command -v mm-cli`. Затем:

```sh
systemctl --user daemon-reload
systemctl --user enable --now mm-cli-watch.service
```

Предварительно войдите: `mm-cli auth login`. Чтобы получать уведомления и о
новых сообщениях, добавьте в `ExecStart=` флаг `--messages`, для сервера, не
являющегося текущим, — `--server <имя>`.

## Проверка работы

```sh
systemctl --user status mm-cli-watch.service
journalctl --user -u mm-cli-watch -f
```

Состояние должно быть `active (running)`. Чтобы увидеть уведомление,
попросите кого-нибудь поставить реакцию на ваше сообщение. Чтобы проверить в
одиночку, добавьте в `ExecStart=` флаг `--include-own`, напишите сообщение
себе (`@me`), поставьте на него реакцию и нажмите на уведомление: сообщение
откроется в приложении. Затем уберите `--include-own`. Снятая реакция
уведомления не даёт (ADR 0024).

## После истёкшей сессии

После уведомления «mm-cli: sign in again» unit остаётся остановленным.
Выполните:

```sh
mm-cli auth login
systemctl --user restart mm-cli-watch.service
```

## Остановка, отключение, удаление

```sh
systemctl --user stop mm-cli-watch.service      # до следующего входа
systemctl --user disable --now mm-cli-watch.service
rm ~/.config/systemd/user/mm-cli-watch.service
systemctl --user daemon-reload
```

## Контейнеры и серверы без графической сессии

Без графической сессии защищённого хранилища нет. Храните токен в файле:
добавьте в секцию `[Service]` строку `Environment=MM_TOKEN_STORAGE=file` (и
входите с той же переменной). Строки про `graphical-session.target` здесь не
применимы; используйте `WantedBy=default.target`. Без службы уведомлений на
шине сессии `--notify` завершается с кодом 1, поэтому на хосте без рабочего
стола запускайте `mm-cli watch --reactions` и читайте вывод в журнале.

## Другие способы

| Способ                               | Плюсы                                 | Минусы                                                                                       |
|--------------------------------------|---------------------------------------|----------------------------------------------------------------------------------------------|
| Автозапуск рабочего стола (`.desktop`) | Запуск при входе; systemd не нужен  | Нет перезапуска после сбоя; нет собственного журнала; код 3 не отличается от других          |
| Из сессии AI-агента                  | Ничего не нужно устанавливать         | Живёт, пока идёт сессия; подходит, когда агент сам читает `--json` (`mm-cli help agents`)    |
| Временный unit, `systemd-run --user` | Те же свойства, что у службы          | Запускать при каждом входе; нужен абсолютный путь к бинарнику (`%h` не раскрывается)         |

## macOS и Windows

В macOS используйте агент launchd, в Windows — задачу планировщика при входе;
обе запускают `mm-cli watch --reactions --notify`.
